# Issue #28: Window: fixed size, no resize or maximize; long pages scroll with the main button always visible

- **Date:** 2026-11-16
- **Branch:** agent/28-fixed-window
- **Action log:** `.claude/logs/2026-11-16.log` on the owner's computer (every step, with times)

## What was asked
The owner doesn't want a resizable or maximizable window. The window should have one fixed size for every page, 460×680 at 96 DPI, scaled for the monitor and shrunk only when the screen is too small. It has only minimize and close, and no resize border, maximize or Snap. When a page is longer than the window, the content scrolls under a fixed header, and the page's main button stays fixed at the bottom. This applies in Arabic and English, light and dark.

## Plan (planner)
- **Window:**
  - Fixed style `0x00CA0000` (caption, system menu, minimize): no resize border, no maximize button, no Snap, and a double-click on the title bar does nothing.
  - `SC_MAXIMIZE` and `SC_SIZE` are ignored in `WM_SYSCOMMAND`, through a tested `allowSysCommand` (no Windows code).
  - Client area 460×680 at 96 DPI, scaled for the monitor and clamped to its work area. `WM_DPICHANGED` keeps the size Windows suggests, so the window doesn't jump between monitors while being dragged.
  - `show()` becomes a single `SW_RESTORE`.
  - Deleted: `minTrackSize`, `WM_GETMINMAXINFO`, the minimum constants and `pIsIconic`.
- **Page:**
  - The page body never scrolls; `main` scrolls, so the header stays at the top.
  - Each screen's buttons are wrapped in a sticky `.actions` bar inside their form, so Enter and submit work as before. When the page fits, the buttons sit right under the fields, as on the web pages. When it doesn't, they stick to the bottom of the window and the text scrolls under them, so they are never cut off.
  - Also: scroll-padding so a focused field isn't hidden under the bar; back to the top on each screen change; an error is scrolled into view.
  - In Arabic the scroll bar is on the left, the native side for right-to-left.
- **Look:**
  - A thin scroll bar in the theme's colours, shown only when needed.
  - A stable, even gutter, so the layout doesn't jump when scrolling starts.
  - A faint line and shadow on the bar only while content is under it, in CSS only.
  - Light and dark through the existing variables. `style.css`, shared with the Hifaz web pages, is not touched; everything new goes in `app.css`.
- **Checks:**
  - Go tests for the size and the system commands.
  - A new `scripts/ui/check-screens.mjs` runs every screen at 460×680 in Arabic and English, light and dark. Each screen must either fit, or scroll with its buttons fully visible and not covered.
  - `test-ui.ps1` checks the fixed style, the exact size, and that maximize and title-bar double-click are ignored.
  - `docs/testing.md` updated.
- **Scope:** the app only (`hifaz.exe`). No protocol change, so protocol-keeper is not needed.
- **PR #30:** only `docs/testing.md` is likely to conflict, and the conflict is trivial.

## Left open
- **BLOCKING (review round 2, not fixed):** `internal/winui/geometry.go:47-56` (`dpiChanged`), called from `window_windows.go:315-322`.
  - **Mid-drag jump:** `WM_DPICHANGED` arrives in the middle of a drag between monitors with different scaling, while the window still overlaps the old monitor. `dpiChanged` clamps and nudges the position onto the new monitor's work area, so the window jumps away from the mouse.
  - **Minimized window:** a window minimized (not hidden to the tray) when the scaling changes is pulled from the minimized position (−32000) onto the screen, while its restore size keeps the old DPI.
  - **Fix:** track `WM_ENTERSIZEMOVE`/`WM_EXITSIZEMOVE`. During a move, use `dpiChanged`'s size with the suggested position, and apply the full clamp and nudge on `WM_EXITSIZEMOVE`, or at once when the DPI changes outside a move. Skip it while minimized, or apply it to the restore rect from `GetWindowPlacement`.
