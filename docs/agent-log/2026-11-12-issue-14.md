# Issue #14: Enrollment restart after two-step setup was saved: wrong text, code wrongly optional

- **Date:** 2026-11-12
- **Branch:** agent/14-enroll-restart-after-mfa
- **Action log:** `.claude/logs/2026-11-12.log` on the owner's computer (every step, with times)

## What was asked
Once two-step setup is saved on the server, a retry gets `invalid_step` at once. The app then says "timed out", and the password screen marks the now-required code as optional, so empty codes count toward the lockout. Fix the fakeserver to refuse a second `enroll/mfa` as the real server does. Say "Enrollment was interrupted", require the code (checked locally), add the missing tests, and add interop cases against the real server code.

## Plan (planner)
- **Fakeserver:** `enroll/mfa` clears `needsSetup`, so a second call gets `invalid_step`.
- **App:**
  - records `mfaDone`;
  - on `invalid_step` after two-step setup, shows `enroll_interrupted` and remembers the link in memory only (`mfaSetLink`, never logged);
  - the next password screen for that link has `code_required`, and the controller refuses an empty code with `code_required` without contacting the server.
- **Tests:** four app tests, using `Requests()` and a `beforeNonce` hook, and five interop cases (`TestWinClientEnrollRestart`).
- **Unchanged:** the service and the protocol.

Not in this issue: after `enroll/mfa`, Confirm could retry `enroll/finish` directly, so the user wouldn't have to type the password again. That was noted on the issue as a later idea.

## What changed (implementer)
- `internal/fakeserver/fakeserver.go`: `enroll/mfa` clears `needsSetup`, so a second call gets `invalid_step`; the `mfaDone` field is removed.
- `internal/app/app.go`:
  - `Controller.mfaSetLink`, kept in memory only;
  - `enrollment.mfaDone` and `enrollment.codeRequired`;
  - `enrollFail` shows `enroll_interrupted` after two-step setup;
  - `enrollPassword` refuses an empty code when one is required, without contacting the server;
  - `mfaSetLink` is cleared on success or when a different link is pasted.
- `internal/app/view.go`: `EnrollView.CodeRequired`, plus the local codes `enroll_interrupted` and `code_required`.
- `internal/ui/web/index.html`, `app.js` and `i18n.js`: the required-code line, no "optional" label when the code is required, and both new texts in Arabic and English.
- `scripts/interop/winclient_interop_test.go.in`: new `TestWinClientEnrollRestart` with the five cases; the setup moved into `newLink()` and `finishRequest()`.
- Tests added or changed:
  - `TestEnrollInterruptedAfterMFA` replaces `TestEnrollStepExpiredReturnsToSetup` and no longer uses `ExpireSteps`;
  - new `TestEnrollEmptyCodeSendsNothing`, `TestEnrollFinishStepExpiredNoMFA` and `TestEnrollMFAWrongCodeKeepsStep`;
  - a `beforeNonce` hook in the test service.

## Review (reviewer)
- Rounds: 1
- Blocking findings and how they were fixed: none. The reviewer ran `make check` and the interop again, and both passed; `../Hifaz` stayed clean. Confirmed against the server code:
  - A required code can never make enrollment impossible: for a user without MFA the server ignores any code (`guard.go`).
  - The empty-code check returns before anything is sent, and the busy state is cleared on every path.
  - The link token is never logged.
  - The tests are not racy.
- Notes left for later (non-blocking):
  1. **The administrator re-issues the link:** the new token isn't remembered, so the code shows as optional again. That was already the case before this change. It could be remembered per server and username instead.
  2. **Lost `enroll/mfa` answer:** if the server saved the secret but the answer was lost, the app shows "timed out" and the code stays optional. This is rare.
  3. **Other errors after two-step setup:** a server error at the last step keeps the user on the two-step setup screen. Confirm then gets `invalid_step` and returns to setup, so the user types the password and code again. Retrying the last step directly (the idea noted on the issue) would avoid this.
  4. **Two-step reset by the administrator after the interruption:** the note "is set up" is then wrong, but harmless, because the server ignores the code.
  5. **Untested:**
     - no test checks that pasting a different link clears `mfaSetLink`;
     - the page's show and hide logic is checked only on Windows.
