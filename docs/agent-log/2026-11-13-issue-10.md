# Issue #10: Tell 'service not running' apart from 'service refused the app'

- **Date:** 2026-11-13
- **Branch:** agent/10-service-error-texts
- **Action log:** `.claude/logs/2026-11-13.log` on the owner's computer (every step, with times)

## What was asked
Every failure to reach the service shows "The Hifaz service is not running … reinstall the app", even when the service is running and refused the app (seen on a real machine: `Access is denied`). Keep the reason when the pipe can't be opened, and show three separate messages in Arabic and English:
- `service_unavailable`: the service isn't running;
- `service_refused`: access denied, or a version mismatch;
- `service_untrusted`: the pipe isn't owned by SYSTEM.

## Plan (planner)
- **Causes:** new `internal/ipc/cause.go` holds three causes that still count as `ErrUnavailable`, and maps Windows error numbers to them; it is tested on Linux.
  - `FILE_NOT_FOUND`, `PIPE_BUSY` or a timeout → not running;
  - `ACCESS_DENIED` → refused;
  - the owner check → untrusted.
- **Failures in the middle of a call:** a broken pipe means not running; a malformed answer means refused.
- **Version mismatch:** the service's `bad_request` ("unknown request") maps to `service_refused`; there is no version handshake on the pipe.
- **Keeping the cause:** `client.go` keeps the cause with `%w: %w`, and `follow()` keeps and logs it.
- **Messages:** `viewError` checks untrusted, then refused, then not running. Texts in Arabic and English.
- **"Nothing was sent":** verified. The owner check runs before any write.
- **Unchanged:** the pipe's wire format and the client protocol.
- **Left out:** the planner suggested a `CHANGELOG.md` entry; it is left to the owner, as for the other issues.

## What changed (implementer)
- `internal/ipc/cause.go` (new):
  - the three causes, each counting as `ErrUnavailable`, plus `ErrNotService` as another name for the untrusted cause;
  - `errBadFrame`;
  - `dialFailure` and `transportFailure`, which keep the original error underneath with `%w: %w`.
- `internal/ipc/ipc.go`: `Read` returns `errBadFrame` for a bad length.
- `internal/ipc/client.go`: dial errors that already have a cause pass through; mid-call failures go through `transportFailure`.
- `internal/ipc/pipe_windows.go`: `CreateFile` errors and the wait timeout go through `dialFailure`, and the owner check fails as untrusted. The owner check is still before any write.
- `internal/app/view.go`:
  - new codes `service_refused` and `service_untrusted`;
  - `viewError` checks untrusted, then refused, then not running;
  - the service's `bad_request` maps to `service_refused`, while the server's is unchanged.
- `internal/app/app.go`: `follow` keeps and logs the cause.
- `internal/ui/web/assets/i18n.js`: the new `service_unavailable` text, plus `service_refused` and `service_untrusted`, in Arabic and English.
- Tests added or changed:
  - `internal/ipc/cause_test.go` (new);
  - `TestClientKeepsDialCause` and `TestClientTransportCause`;
  - `internal/app/view_test.go` (new): a table test for `viewError`;
  - `TestEnrollServiceDownAtLink` now covers four causes; new `TestFollowServiceRefused`;
  - Windows only: `TestDialMissingPipe`, `TestDialAccessDenied`, and `TestDialChecksOwner` extended.

## Review (reviewer)
- Rounds: 1
- Blocking findings and how they were fixed: none. The reviewer ran `make check` again, and the `ipc` and `app` tests uncached; all pass. Confirmed:
  - The owner check still runs before anything is written, on both the query and the control connection. The pipe's security is unchanged: SDDL, reject-remote, first instance, identification level, and the access requested.
  - "Untrusted" is shown only when the owner was read and isn't SYSTEM.
  - The causes match correctly, and the order in `viewError` is right.
  - The `ask()` retry still decides on the raw error.
  - `TestDialAccessDenied` is sound on an elevated runner, as long as the runner doesn't run as SYSTEM.
- Notes left for later (non-blocking):
  1. **Every `bad_request` from the service shows "refused, install the latest version".** That includes cases a reinstall won't fix: "unknown caller" (`engine.go:123`) and "invalid identity key" (`engine.go:266`). This was approved in the plan; a separate code for "unknown caller" could follow.
  2. **The `ERROR_SEM_TIMEOUT` (121) mapping can never be reached:** `dial` ignores what `WaitNamedPipe` returns. It is harmless, but its comment could mislead.
  3. **A pipe still busy after the wait shows "not running".** This is rare.
  4. **Unexpected answers count as "not running":** other decode errors and "message too large" are classified that way. Neither is realistic today.
  5. **The session log can now include the pipe owner's SID** in the untrusted case. A SID is not secret.

## Protocol (protocol-keeper)
Not needed. Nothing changed in the client protocol, the test vectors or the versions, and the pipe's wire format between the app and the service is unchanged.

## Left open
- Windows CI must run `TestDialMissingPipe`, `TestDialAccessDenied` and the extended `TestDialChecksOwner`. If CI ever runs as SYSTEM, `TestDialAccessDenied` would fail.
- Notes 1–2 could be a small follow-up: a separate code and text for "unknown caller", and removing or fixing the 121 mapping.
- `CHANGELOG.md` is left to the owner. The new and changed messages belong in the next release notes.
