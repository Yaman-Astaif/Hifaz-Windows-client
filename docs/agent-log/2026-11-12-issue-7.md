# Issue #7: Guide users who were enrolled before: renewal link after reinstall, device link on another computer

- **Date:** 2026-11-12
- **Branch:** agent/7-returning-users
- **Action log:** `.claude/logs/2026-11-12.log` on the owner's computer (every step, with times)

## What was asked
A user who was enrolled before (reinstall, second computer) gets no hint of what to do: the app only offers a new enrollment. Without changing the protocol or the server, tell them which link to ask for (`renew` for this computer, `device` for another), greet `renew` links with "Welcome back", fix the password text, and document it in the README.

## Plan (planner)
Only the page changes; no Go code, protocol or service changes. `app.js` works out `enroll.renew`, `enroll.new_device` and `enroll.renew_text` from `enroll.kind`. `index.html` adds the line for returning users on the setup screen and a separate "Welcome back" title and text for `renew` links. `i18n.js` adds `setupReturning`, `renewTitle`, `renewDevice` and `renewSub` and changes `enrollSub`, in Arabic and English. A new test, `TestEnrollRenewLink`, runs against the fakeserver, and the `enroll()` helper now checks the kind is `device`. `README.md` gets a section "Reinstalling or using another computer". Open question, not blocking: `CHANGELOG.md` is left to the owner.

## What changed (implementer)
- `internal/ui/web/assets/app.js`: `enroll.renew`, `enroll.new_device` and `enroll.renew_text` are worked out from `enroll.kind`. In `enroll.renew_text`, the device name is isolated with U+2068/U+2069 and set as text only.
- `internal/ui/web/index.html`: the setup screen gets the `setupReturning` hint. The password screen shows the new-device or renewal title and text depending on the link type.
- `internal/ui/web/assets/i18n.js`: Arabic and English add `setupReturning`, `renewTitle`, `renewDevice` and `renewSub`; `enrollSub` becomes "Enter your password." The Arabic reuses the app's existing terms (المصادقة الثنائية, رمز التحقق).
- `README.md`: a new section "Reinstalling or using another computer".
- Tests added or changed: `TestEnrollRenewLink` (`internal/app/app_test.go`); the `enroll()` helper now checks the kind is `device`. The Go code did not change, so the new test passed at once; it pins the behaviour the page relies on.
