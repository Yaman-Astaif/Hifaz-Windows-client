# Issue #5: Normal users cannot reach the service: pipe opened with GENERIC_WRITE, DACL grants only read + FILE_WRITE_DATA ("service not running, reinstall")

- **Date:** 2026-11-12
- **Branch:** agent/5-pipe-access
- **Action log:** `.claude/logs/2026-11-12.log` on the owner's computer (every step, with times)

## What was asked
A normal (non-elevated) user always gets "The Hifaz service is not running" because `dial` opens the
pipe with `GENERIC_READ | GENERIC_WRITE`, while the pipe DACL grants interactive users only
`FILE_GENERIC_READ | FILE_WRITE_DATA`. Open the pipe with `GENERIC_READ | FILE_WRITE_DATA`, keep the
DACL, and add a regression test that fails on an elevated CI runner too.

## Plan (planner)
- `dial` opens the pipe with `GENERIC_READ|FILE_WRITE_DATA` instead of `GENERIC_READ|GENERIC_WRITE`. The DACL is unchanged.
- The interactive users' mask becomes a shared constant `userAccess` (`0x12008b`). `pipeSDDL` is built from it and stays byte-identical.
- New Windows tests grant only that mask to the current user, with no `BA` entry, so they fail on elevated CI if the bug returns:
  - a dial round trip;
  - a second server instance is refused with `ERROR_ACCESS_DENIED` (with a full-access control case);
  - a check that the mask has no `FILE_CREATE_PIPE_INSTANCE` bit.
- The tests grant the mask to the user's SID rather than `IU`, because the runner's token may not have INTERACTIVE.
- The clearer "access denied" message is left for a follow-up issue.
- Open question (it does not change the code): whether to add a `CHANGELOG.md` entry. There is no Unreleased section, and the owner writes release notes, so none was added.

## What changed (implementer)
- `internal/ipc/pipe_windows.go`:
  - new `const userAccess = "0x12008b"`;
  - `pipeSDDL` is built from it (byte-identical);
  - `dial` opens the pipe with `GENERIC_READ|FILE_WRITE_DATA`, with a comment explaining why.
- `docs/testing.md`: the Windows CI pipe checks now list normal-user access rights.
- Tests added in `internal/ipc/pipe_windows_test.go`:
  - `restrictedPipe` helper: only `userAccess`, granted to the current user, no `BA` entry;
  - `TestDialWithUserAccess`: dial and round trip;
  - `TestUserCannotAddServerInstance`: a second instance without the first-instance flag gets `ERROR_ACCESS_DENIED`, and a full-access control case succeeds;
  - `TestUserAccessMask`.
